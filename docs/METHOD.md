# Method

This page explains every number binaudit shows, so that a reader can check it by hand.

## What one audit is

One audit is one bin, opened once, on one date. Each item found in it is recorded with the
stream it belongs to. An item can have a count (three tea bags) and, optionally, a weight
in grams.

Streams follow India's Solid Waste Management Rules, 2016:

| Stream | In the rules | Examples in the catalogue |
|---|---|---|
| wet | biodegradable waste | peels, cooked food, tea leaves |
| dry | non-biodegradable waste | paper, plastic, glass, metal, wrapped sanitary waste |
| hazardous | domestic hazardous waste | batteries, CFL bulbs, expired medicines, used syringes |

The bundled catalogue has 60 common items. Cities sort some items differently (soiled
tissue, greasy pizza boxes), so the stream of every item stays editable.

## Contamination rate

For one site, one bin stream and one phase:

```
rate = misplaced items / all items
```

where an item is misplaced when the stream it belongs to differs from the bin it was found
in. Counts are pooled over all audits in the group. When every row in a group has a
weight, the same ratio is computed in grams (`mass_rate` in `binaudit summary --json`).

## Interval

Items from one bin on one day are not independent: a single takeaway order can put five
wrong items in the same bin. Treating items as independent (a binomial or Wilson
interval) would make the interval too narrow. binaudit therefore uses a cluster
bootstrap:

1. Take the audits in the group, say n of them.
2. Draw n audits with replacement and compute the pooled rate.
3. Repeat 2,000 times.
4. Report the 2.5th and 97.5th percentiles (type 7 quantiles, the default in R and NumPy).

The random generator is mulberry32 with seed 7, implemented the same way in JavaScript
and Python, so the same data always gives the same interval in both. The Wilson interval
is also computed (`ci_wilson`) for comparison.

A group with one audit gets no interval ("needs 2+ audits"). A group with fewer than
5 audits or fewer than 30 items is flagged as a small sample.

## Did it change?

For one bin, two phases (for example "before sign" and "after sign"):

```
difference = rate after - rate before
```

The interval comes from 2,000 draws that resample audits within each phase
independently. The reading is:

| Interval | Reading |
|---|---|
| entirely below 0 | fewer misplaced items after |
| entirely above 0 | more misplaced items after |
| includes 0 | no clear change |

A before/after change can come from anything that changed between the phases: exams,
festivals, a new cleaner. Audit a similar bin that got no sign over the same weeks. If the
signed bin improves and the unsigned one does not, the sign is the likely reason. The
synthetic sample is built this way: floor 2 gets a sign, floor 3 does not.

## Synthetic sample

`web/data/sample-audits.csv` is generated by `binaudit sample` from fixed probabilities
in `src/binaudit/sample.py`. It is not a measurement and the app labels it as synthetic
whenever it is loaded. Its only purpose is to demonstrate the app and to give the tests a
known answer: the generator plants a drop in the floor 2 wet bin and no change in the
floor 3 dry bin, and the tests check that binaudit finds exactly that.

## Same numbers in both implementations

`tests/test_parity.py` runs the JavaScript core (`web/js/stats.js`) under Node.js and the
Python package on the same CSV and requires every rate, interval and comparison to agree
within 1e-12.
